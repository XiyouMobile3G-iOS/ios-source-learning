# 面试回答与追问链风格设计

## 目标

为教学提示词库增加一种可组合的面试风格：用户表达面试语义时自动启用，在默认渐进式教学法的节奏下，生成可直接口述的回答，并沿最可能的面试追问逐层训练。

## 触发规则

当用户的意图包含面试、面试官、面试题、怎么回答、如何回答或追问等语义时，教学索引在默认方法之外叠加面试风格。普通源码学习不加载该风格。

触发依据是语义而不是严格关键词匹配。例如“这个问题面试时怎么说”和“面试官接下来会问什么”都应触发；单纯询问技术原理则不触发。

## 组合模型

- `methods/progressive-dialogue.md` 继续控制单轮粒度、停止条件和互动节奏。
- `styles/interview-answer.md` 只控制面试回答的组织方式与追问策略。
- 组合时先遵守方法，再应用风格；风格不得一次倾倒整棵追问树。
- 用户明确要求一次讲完时，沿用默认方法已有的退出机制，允许输出完整主回答与追问链。

## 单轮输出协议

1. 给出一段 30–60 秒、可直接口述的主回答，采用“结论 → 核心机制 → 边界条件”的结构。
2. 回答中保留一个自然且准确的追问钩子；不故意卖关子，也不添加无关术语。
3. 只指出一个最可能沿该钩子出现的追问。
4. 让用户先尝试回答该追问；下一轮根据用户答案纠正，并给出更好的口述版本。
5. 当前追问处理完成后，再进入下一层追问。

## 质量约束

- 回答要像候选人口述，不写成教科书、论文或关键词堆砌。
- 优先覆盖定义、机制、边界、对比和实践取舍等高概率追问。
- 不编造项目经历、性能数据或未由源码支持的事实。
- 不为了制造追问而留下错误、歧义或误导性结论。
- 如果原问题过大，先给核心回答，再沿一个方向逐层深入。

## 文件与注册

- 在 `prompts/teaching/INDEX.md` 增加可用风格表、语义触发条件和组合顺序。
- 根 `AGENTS.md` 与 `CLAUDE.md` 不修改。

## 验证

- 索引能从面试语义路由到新风格。
- 默认方法仍是唯一默认教学方法。
- 普通讲解不会无条件加载面试风格。
- 风格文件包含口述回答结构、单条追问、等待用户回答及一次讲完例外。
- 根入口文件没有发生变化。
